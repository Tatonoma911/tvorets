# QA интерактивных сайтов: опыт PADEL-NSK
Дата: 15.10.2026. Применение: редизайн существующего сайта, touch-интерфейсы, анимации действий, галереи, липкие панели. Это дополнение к разделу 8 TVORETS.md, а не обязательная архитектура каждого проекта.

## Сначала договор о поведении
Сохрани карту исходных текстов, услуг, контактов, цен, маршрутов и ссылок записи. Редизайн не разрешает заново сочинять согласованные тексты. Отделяй добавленные предложения от оригинала. Запиши роль каждого референса: фотографии, геометрия, типографика или движение; ссылка сама по себе не доказывает просмотр.

Для изменяемой функции зафиксируй вход → видимая реакция → момент действия → итог. Разделяй mouse, touch, pen и keyboard. Новое требование только для телефона не должно менять принятую механику desktop. Точный темп, цвет, траектории и ракетки PADEL — решения этого проекта, не универсальный стиль Творца.

## Проверки по симптомам
| Симптом / пример | Что проверить | Критерий приёмки |
|---|---|---|
| Кнопка срабатывает до прилёта декоративного мяча | Независимые click/pointerup обработчики и таймеры; отдельные canvas-компоненты | Один владелец активации; действие ровно один раз в согласованный момент контакта; при отмене/ошибке анимации интерфейс не зависает |
| Телефон переключает кнопку в серое с задержкой | Залипающий hover, transition:all, transition-delay, очередь эффектов | Скролл не имитирует наведение, завершённый тап возвращает понятное состояние; проверено быстрое повторное касание |
| После свайпа возникает случайный клик | Смещение pointerdown→pointerup, pointercancel, второй палец, long press | Прокрутка и отменённый жест не запускают действие; порог выбран под продукт, а не скопирован вслепую |
| Курсор исчезает в галерее | Native dialog/top layer, CSS cursor:none, положение canvas/popover | Ракетка видна поверх модального окна либо доступен системный курсор; работают фото, стрелки, закрытие, Escape и возврат фокуса |
| На телефоне внутри модального окна нет эффекта | Отдельная touch-ветка, слои, скрытая desktop-настройка | Мобильное действие не зависит от недоступного переключателя; эффект виден, не перехватывает касания |
| Фото тренера нажимается, но описание не видно | Стабильный ID, раскрытие нужного блока, sticky header, горизонтальная карусель | Каждый портрет открывает своё описание и прокручивает к нему без перекрытия; повторное нажатие не закрывает уже открытый текст |
| Телефоны и кнопки соседних карточек на разных уровнях | Одно- и двухстрочные адреса, общие строки grid/flex | Выравнивание сохраняется на узком экране и с длинным текстом без ручных пробелов |
| Пустые слоты / старые фотографии | Соответствие записи asset-файлу, успешная загрузка, cache key, полный набор | Все видимые ячейки заполнены; миниатюра и полноразмерное фото правильные, счётчик совпадает с набором |
| Петля прыгает, ракетка не попадает по мячу | Фаза, контакт, pivot ручки, позиция и скорость на границе цикла | Движение и контакт согласованы; на стыке нет скачка положения и заметного рывка скорости |
| Мяч возвращается в лицо вместо бокового отскока | Масштаб по глубине, viewport-координаты, траектория после контакта | Поведение соответствует согласованному варианту устройства, без непреднамеренного увеличения; визуально просмотрено |
| Два мяча вместо одного | Legacy DOM, CSS-анимация и новый renderer одновременно | Один согласованный источник эффекта; перезагрузка и повторное включение не создают дубликаты |

## Анимация — часть функции
Если пользователь согласовал активацию в момент удара, связывай действие с фактической фазой/завершением полёта. Отдельный setTimeout с похожим временем расходится с анимацией при нагрузке, отмене и изменении длительности. Учитывай reduced motion: функция остаётся доступна без обязательного ожидания декоративного полёта. Keyboard-активацию проверяй отдельно, не выдумывай координаты указателя.

Для ссылок в новое окно и видео проверь ограничения пользовательской активации браузера: отложенный вызов может блокироваться, особенно в Safari. Не объявляй этот случай исправленным по desktop Chromium. При недоступном устройстве укажи конкретную непроверенную ветку. Не создавай лишние окна и не отправляй реальные заявки ради теста.

Проверяй не только красоту одного движения, но и быстрые повторные наведения, тап во время анимации, уход со сцены, закрытие диалога, resize и возврат вкладки. Не допускай накопления бесконечной скорости и очередей. Размытие и squash/stretch должны следовать направлению и скорости, а не постоянно деформировать предмет. Плавная петля требует согласования положения и скорости. Если нужен одинаковый темп на разном расстоянии, длительность вычисляется из расстояния и скорости, а не подбирается одним таймером для всех целей.

Native dialog находится в верхнем слое браузера: увеличение z-index обычного body-canvas не гарантирует видимость поверх него. Возможный вариант — отдельный manual popover для эффекта с pointer-events:none; проверь порядок открытия и закрытия. При неподдерживаемом API сохрани системный курсор и основное действие. Справка: https://developer.mozilla.org/en-US/docs/Web/API/Popover_API/Using . Это технический вариант, не обязательная зависимость всех сайтов.

## Как доказывать исправление
1. Воспроизведи конкретный дефект в текущей версии; запиши URL/commit, устройство или эмуляцию, размер viewport, тип ввода, состояние настройки эффекта и шаги.
2. Проверь исправленный сценарий и соседние ветки: desktop/touch, модальное/обычное состояние, повторное действие. Для небольшого фиксированного набора проверь все элементы: один тренер не доказывает остальные девять.
3. Визуально проверь обычный viewport, а не только уменьшенный fullpage. Для mobile-first сайта начни с телефона: адреса, номера, запись, раскрытия, галерея, sticky header, карусель. Матрица ширин выбирается по рискам; для PADEL использовались 320/360/390/430/768/1280.
4. Запиши отдельно: проверка логики, браузерное действие мышью, touch-эмуляция, физический iOS/Android. Узкая ширина браузера не доказывает touch, синтетический event не доказывает пользовательский жест. Отсутствие console errors не доказывает правильную анимацию.
5. Сопоставь локальную проверку, упакованный commit и опубликованную версию. После выпуска проверь живой ключевой сценарий и актуальные ресурсы; сохранение версии не равно публикации. Исторический PASS не переносится на последующие правки.

Краткая запись доказательства: версия/URL; шаги; ожидаемое; наблюдаемое; тип ввода и viewport; скриншот или запись движения; PASS/FAIL/NOT TESTED; точная оставшаяся зависимость. Используй существующий журнал проекта, не создавай бюрократию ради таблицы.

## Разбор PADEL-NSK и границы доказательства
В ходе итераций пользователь выявил: два мяча в шапке; мобильный tap до контакта; залипающий hover; конкурирующий запуск 3D-ракеток; неестественную перспективу и отскок; разные требования к desktop/mobile; перекрытие курсора модальным окном; несогласованные якоря тренеров; пустые слоты и устаревшие портреты. Это реальные регрессии, а не гипотетические запреты.

На 15.10.2026 локально наблюдались: native gallery открыта, ракетка видна над изображением, переход 1→2 из 16 работает; раскрытие описаний через портреты проверяется по каждому тренеру. Мобильные сценарии на физическом устройстве и перенос на Tilda не подтверждены. Эта запись не является актуальным сертификатом всего сайта: дальнейшие результаты смотри в журнале проекта.
