# Творец 1.6

**От идеи своими словами до работающего, проверенного результата с ИИ-агентом.**

Творец — набор инструкций, проверок и шаблонов для создания и доработки сайтов, приложений, игр и таблиц. Он помогает агенту понять задачу, принять обычные технические решения, собрать продукт, найти ошибки и показать доказательства работы. Автор — **Антон Казаков**, [@kazakovant](https://t.me/kazakovant).

Комплект доступен бесплатно. В нём нет обязательной регистрации, передачи данных автору, искусственного лимита задач или встроенной платной версии. Платформа ИИ, модели, хостинг и сторонние сервисы могут иметь собственную стоимость.

## Кому и зачем

- Эксперту или предпринимателю, который знает свою задачу, но не хочет писать техническое задание на языке разработчиков.
- Дизайнеру, преподавателю и автору продуктов, которым нужен открываемый прототип с понятной логикой.
- Разработчику, который передаёт агенту диагностику, исправление багов и проверку существующего проекта.
- Команде, которой важно продолжать работу после перерыва и передавать результат без потери контекста.

Можно начать с фразы «нужен инструмент, который из запроса клиента собирает предложение», картинки или существующего проекта. Агенту понадобятся реальные средства чтения файлов, выполнения кода и просмотра результата. Сам Markdown ничего не запускает.

## Начать за минуту

Скачайте репозиторий, откройте отдельную папку проекта в среде ИИ-агента и передайте ему комплект с таким сообщением:

> Прочитай TVORETS.md и работай как Творец. Хочу сделать [что] для [кого], чтобы человек мог [главное действие и результат]. Доведи до работающего результата и сам проверь. Обычные технические решения принимай самостоятельно. Если не хватает важной информации, сначала изучи доступные материалы. Покажи, что работает, и отдельно укажи ограничения.

Подробный запуск: [QUICKSTART.md](QUICKSTART.md). Основной файл [TVORETS.md](TVORETS.md) самодостаточен. Дополнительные материалы нужны по задаче, а не как обязательное чтение перед первым действием.

## Что умеет направлять

| Задача | Как организована работа |
|---|---|
| Создать новый продукт | Цель и пользовательский путь → короткий работающий образец → реализация → проверка и передача |
| Исправить существующий проект | Воспроизведение → причина → минимальное исправление → регрессионная проверка |
| Проверить пользу | Кто вводит какие данные, что получает и решает ли это исходную проблему |
| Проверить интерфейс | Реальный экран, узкий viewport, читаемость, состояния, клавиатура и touch по применимости |
| Проверить данные | Собственный ввод, ошибочные значения, отмена, повтор, сохранение и восстановление |
| Организовать исполнителей | Единственный владелец участка, границы и приёмка, работа по зависимостям при доступной команде |
| Продолжить после паузы | Сверка текущих файлов с целью, решениями, отменёнными требованиями и доказательствами |
| Передать результат | Открываемый артефакт, исходники, запуск из новой папки, ограничения и следующий шаг |

## Практические преимущества подхода

**Меньше ручного микроменеджмента.** Обычные размеры, структура кода и исправления остаются у агента; существенные решения обсуждаются понятными вариантами. Это правило работы, а не измеренное обещание экономии времени.

**Ошибки становятся воспроизводимыми.** Агент должен показать условие возникновения, исправить причину и повторить сценарий. Проверка существования файла не подменяет запуск приложения.

**Контекст сохраняется вместе с проектом.** Шаблон состояния фиксирует цель, решения, текущую версию и незавершённые проверки. Это снижает риск продолжить отменённую задачу или перенести старый PASS на новый код.

**Проверяются реальные действия.** Ввод, редактирование, отмена, повторный запуск и ограничения важнее количества экранов и декоративных кнопок.

**Доказательства отделены от обещаний.** PASS, FAIL, BLOCKED и NOT_RUN имеют разный смысл. Утилита проверки целостности не выдаёт разрешение на релиз и не подтверждает качество сама по себе.

**Нужен минимальный доступный набор инструментов.** Базовый путь использует средства среды, обычные HTML/CSS/JavaScript и Python там, где это подходит. Для другой задачи выбирается подходящий инструмент: фреймворк не требует превращать всё в сайт.

Сравнительное исследование производительности с другими подходами не проводилось. Нельзя обещать универсальный результат или фиксированное ускорение.

## Границы и безопасность

Творец — инструкции для работающего агента, **не фоновая служба мониторинга**. Наблюдение продолжается только пока агент действительно запущен; регулярные запуски требуют отдельно настроенного механизма.

Комплект не поставляет модель, IDE, хостинг, доступы, сервер или готовую интеграцию. Он не обходит ограничения среды, не разрешает платежи, публикацию, удаление и передачу данных без соответствующих полномочий. Пользовательские секреты не должны попадать в документы и доказательства.

Установка на другом компьютере, другие модели и платформы, физические телефоны и production backend не покрыты указанными испытаниями. Для каждого продукта нужны собственные проверки и оценка рисков. Навык не заменяет специалиста при медицинских, юридических и других высокорисковых решениях.
