# Проверки изменения 1.7 — 16 октября 2026

## Область изменения

Творец сохраняет управление всей начатой задачей, цель, полномочия и общую приёмку. Специализированные навыки получают ограниченный участок; маршруты и примеры не являются закрытым списком возможностей. Добавлен SKILL-ORCHESTRATION.md. Локальные адаптации сторонних навыков не объявляются upstream-правилами и не включены целиком в публичный комплект.

## Независимый обзор совместимости

Исполнитель, отличный от автора основных изменений, прочитал актуальные инструкции и сверил восемь ранее найденных рисков. Исправлены:

| Риск | Проверенная договорённость |
|---|---|
| HTML / PPTX / Google Slides | Формат задачи определяет основной процесс; один способ пишет один артефакт |
| Выбор темы прежде цели | Сначала цель и формат; принятый бренд сохраняется, делегированный дизайн не требует опроса из 50 тем |
| Конкурирующие PPTX-движки | Выбор одного доступного authoring pipeline, без параллельного пересоздания файла |
| Объявление runtime установленным | Реальная проверка dependencies/renderer; установка только в полномочиях |
| Жёсткий лимит двух QA-проходов | Ограничивается необязательная полировка; подтверждённая ошибка/доступность/критерий остаются обязательными |
| Придуманная цель из дизайнерского примера | Предложение отдельно от цели владельца; существенный пробел останавливает зависимое выполнение |
| System fonts против strict warning | Применимые дефекты исправляются; неприменимая проверка документируется/адаптируется без ложного strict PASS |
| Неизвестный стек и делегированный новый проект | Обнаруженный стек отличается от самостоятельно выбранного нового; вопрос только о существенном ограничении |

Приветствия Emil/animate ограничены прямым вызовом без содержательной задачи. Humanizer применяется к текстовому фрагменту, сохраняя факты/голос/цитаты/код и требования всей поставки.

Первые точечные правки пропустили дублирующие положения slides о strict warnings/50 темах и зависимости PPTX; независимый обзор обнаружил и исправил их в установленных копиях. Оригиналы сохранены отдельно в skill-adaptations перед адаптациями. Проверка не утверждает, что любая будущая модель всегда правильно разрешит конфликт.

## Фактические проверки

- PASS: 13 существующих unit tests утилиты доказательств. Они не проверяют выбор навыков.
- Проверены ссылки и совпадение канонической/установленной/публичной копий актуальных материалов; SHA-256 manifest привязан к выдаваемому содержимому.
- PASS: quick_validate установленного навыка после исправления YAML description. Первоначально 1.7 выявлена YAML-ошибка из-за неэкранированного двоеточия; исправление проверено до публикации.
- NOT_RUN: новый полный поведенческий прогон агента, создание презентации/сайта и runtime-испытания всех адаптированных навыков. Настоящий запуск и принятие продукта остаются отдельной проверкой.

Исторические отчёты 1.4–1.6 не переписаны и не доказывают новое поведение 1.7. Исходный read-only аудит и рабочие журналы остаются в проекте интеграции; приватные пути, пользовательские проекты и лицензированные полные навыки не включены в публичную поставку.

Проверен новый раздел последовательности: вход → средство → выход → проверка → потребитель, зависимости пересчитываются по изменениям; независимые этапы могут идти параллельно. Сочетание инструментов разрешено по их вкладу, без фиксированного количества; запрещена конфликтующая одновременная запись, а не полезная последовательная обработка. Это ручная проверка инструкции, не измерение исполнения конвейера моделью.
