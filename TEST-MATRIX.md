# Тесты по риску и типу продукта

Составь короткую таблицу «обещание пользователю → возможный ущерб → проверка → доказательство». Большой список тестов не цель. Больше внимания необратимой записи, деньгам, правам, миграциям и основному сценарию; декоративные детали проверяй соразмерно. Не выбирай все строки ниже механически.

| Область | Когда нужна | Что действительно проверить |
|---|---|---|
| Основной путь | Любой продукт | Пользователь может начать, выполнить полезное действие и получить результат; результат проверен независимо |
| Границы входа | Числа, текст, файлы, даты | 0/1/max, пустое, пробелы, Unicode/кириллица, очень длинное, неверный формат, отрицательное, NaN, неверный timezone; ошибки не дают частичной записи |
| Последовательности | Игры и приложения со состоянием | Start→Next→Back→Reload; Save→Cancel; смена режима/языка; повторный click/Enter/Space; порядок и остатки согласованы |
| Асинхронность | Фото, поиск, API, автосохранение | Старый ответ после нового, отмена во время работы, reset→поздний callback, уход со страницы, повтор после timeout; не применяются устаревшие результаты |
| Хранение | Есть пользовательские данные | Повторный запуск, новая/старая схема, повреждённый файл, квота/запрет, backup/restore, две вкладки; ошибка сохранения не маскируется успехом |
| API и контракты | Есть интеграции | Валидный ответ, malformed/empty, timeout, offline, 401/403/404/409/429/500, повтор запроса, границы прав; fixture не выдаётся за живой сервис |
| Права и приватность | Есть роли/пользовательские данные | Один пользователь не видит чужое; нельзя обойти контроль прямым запросом; секреты не попадают в UI/log/export; опасный пользовательский текст не исполняется |
| Доступность и UI | Есть интерфейс | Реальный click, focus/Tab/Escape, понятные имена, contrast, ошибки формы, длинные языки, reduced-motion; touch и desktop различаются; см. WEB-INTERACTION-QA.md |
| Адаптив | Несколько экранов | Критические состояния на узком и широком экране, малая высота, увеличение текста, действительная достижимость действия; geometry плюс визуальный просмотр |
| Таблицы/расчёты | CSV/XLSX/отчёты | Независимый контрольный расчёт, округление, пустые/дубли/даты, единицы, локаль, формулы после пересчёта, экспорт и повторное открытие |
| Игры | Счёт, ресурсы, время | Инварианты победы/поражения, лимиты, пауза/возврат, save/load, повтор старта, ввод во время перехода; детерминированные seed и время для теста |
| Производительность | Есть заметный риск | Измерить время/размер/память на типичном и большом допустимом наборе; установить бюджет по продукту, сравнить с baseline; не называть единичный замер нагрузочным тестом |
| Поставка | Есть сборка/публикация | Чистый запуск из выдаваемого пакета, нужные assets/dependencies, отсутствие dev-секретов и абсолютных личных путей; совпадение проверенной и выданной версии |

## Углубление по наблюдаемым рискам

- Property-based: сформулируй независимое свойство, например баланс неотрицателен, экспорт→импорт сохраняет смысл, сортировка не меняет множество элементов. Генерируй входы с воспроизводимым seed; сохраняй минимальный контрпример. Случайные клики без проверяемого свойства мало что доказывают.
- Model-based: для нескольких состояний опиши допустимые переходы простой независимой моделью. Проверяй последовательности, а не только отдельные кнопки. Не копируй реализацию в эталон.
- Metamorphic: если точного ответа нет, проверяй отношения: удвоение количества удваивает сумму до округления; перестановка независимых строк не меняет итог; смена языка не меняет ID и остатки.
- Mutation: временно убери защиту или поменяй граничное сравнение в отдельной копии. Если важный тест остаётся зелёным, он не защищает поведение. Не модифицируй production ради эксперимента.
- Fault injection: локально управляй отказом хранилища, временем, ответом сети или порядком callback. Отметь, что это имитация; затем отдельно проверь доступный настоящий путь.
- Визуальная регрессия: сравнивай важные состояния с принятым образцом, учитывай шрифты/масштаб и динамические области. Не перезаписывай эталон без проверки, что изменение действительно принято.

Используй установленный раннер и поддерживаемые инструменты среды. Playwright, Hypothesis, fast-check, Stryker и другие — варианты, не обязательные зависимости. Не устанавливай весь набор в каждый проект. Когда браузер разрешён только через конкретный инструмент, используй его; внутренние функции и headless-обход не равны проверке пользовательского пути.

## Честность теста

Различай PASS, FAIL, BLOCKED и NOT_RUN. Skip/timeout/пустая выборка не равны PASS. Объясни pre-existing failures отдельно от внесённых. Повторяющийся flaky-тест сохраняет исходный сбой и расследование; случайный зелёный повтор не закрывает проблему. Мок оценивает ветку клиента, а не доступность backend. Самооценка агента не является независимой экспертизой.

После изменения повторяй затронутые тесты и необходимые зависимости; полный прогон нужен при общей причине или перед соответствующей поставкой. Не запускай бесконечно уже пройденные проверки без новых изменений. Новая версия делает прежнее доказательство для изменённого участка устаревшим.
