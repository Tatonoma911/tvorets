# Маршрутизация продукта и средств

Используй **после обязательного допуска по цели** в разделе 1 TVORETS.md и до существенной реализации. Сам выбери подходящий маршрут, прочитай лишь нужные знания/навыки и обнаружь реальные инструменты среды. Не спрашивай владельца выбирать каждую библиотеку. Если неясна цель или критерий — сначала вопрос владельцу, а не выбор маршрута.

## Выбери основной путь

| Сигнал задачи | Полезный выход и ключевая структура | Знания/средства по необходимости | Наблюдаемая приёмка |
|---|---|---|---|
| Сайт / приложение с интерфейсом | Один основной пользовательский путь, ввод → действие → результат; responsive, состояния, сохранение при необходимости | Реальный стек проекта; релевантные UI/UX навыки; доступный browser/runtime. Внешний API — только если он нужен цели | Открыть текущую сборку; пройти основной путь с собственным вводом, ошибкой/отменой и нужным сохранением; проверить телефон/desktop, focus/touch/читаемость. Скриншот не доказывает логику |
| Игра | Core loop: вход/управление → действие → понятная обратная связь → прогресс, поражение/успех или иной критерий окончания; новый запуск/save если обещаны | Сначала движок и существующий проект. Учебник Build Your Own X — для конкретной механики/обучения, не требование писать движок. 3D/звук/генерация только доступными средствами | Запустить playable runtime и самому сыграть цикл; проверить ввод, fail/win или оговорённые состояния, restart и save/load при обещании. Рендер, код и заставка не равны игре |
| CRM / рабочая система | Сущности и связи, роли/права, жизненный цикл записи; импорт, конфликты, история и отчёт лишь по цели | Существующая база/backend/auth; схема и ограниченный CRUD; API/MCP по фактическим потребностям. Не добавляй роли, которых нет в задаче | Создать/изменить/найти/удалить или отменить запись по контракту; проверить связи, повторы/конфликт импорта и сохранение. Для обещанных ролей — разрешённая и запрещённая операция разными пользователями. UI-переключатель роли не доказывает серверные права |
| Маркетинг / продвижение | Аудитория и ситуация → подтверждённая проблема → предложение → путь заявки → материалы и измерение | Источники аудитории/оффера; уместные навыки текстов, дизайна, Reels, документов; аналитика только если реально доступна | Утверждения связаны с источниками/статусом гипотез; материалы отрендерены/прочитаны в целевом масштабе; CTA и путь заявки проверены. События аналитики либо проверены, либо явно готовы к настройке. Не придумывать конверсии, отзывы и реальные кейсы |
| Бот / автоматизация | Триггер → данные → обработка → полезный ответ/действие; состояния диалога и повтор | Сначала имеющийся коннектор/API; runtime/webhook/auth когда нужны. UI-симуляция допустима только как согласованный прототип | Проверить реальное сообщение/событие до результата и релевантные повтор/ошибку; внешние отправки только при разрешении. Экран чата не доказывает работающий Telegram-бот |
| Документ / презентация / контент | Получатель, решение, формат и завершённый материал | Соответствующий навык документа/PDF/слайдов/монтажа и доступный renderer | Открыть/отрендерить выдаваемый файл, проверить содержание, читаемость, ссылки и нужную редактируемость. Исходный Markdown не заменяет запрошенный DOCX/PDF |
| Дашборд / таблица / анализ | Вопрос пользователя → источники/период → расчёт → читаемый вывод/действие | Реальные данные или явно согласованные примеры; формулы/агрегации, соответствующие инструменты | Сверить ключевые цифры независимым расчётом, фильтры/пустые данные/период; повторить обновление при обещании. Декоративные цифры не доказывают связь с источником |

Комбинируй маршруты, когда этого требует один полезный результат (например, сайт + бот), а не ради количества компонентов. Сначала проверь самый короткий сквозной путь и рискованный стык; не строй все слои заранее.

## Обнаружение вместо выдуманных возможностей

1. Проверь файлы/стек и реально доступные навыки, API, плагины, CLI и runtime. Название инструмента или каталог серверов не подтверждают подключение и auth.
Для UI/motion подходящим кандидатом может быть `emil-design-eng`, если он действительно обнаружен и прочитан; его наличие не предполагается у получателя комплекта. Playwright MCP предлагай для интерактивного прохождения форм, навигации и мобильного UI, когда это снимает конкретную неопределённость; локальный Playwright runner удобен для повторяемых регрессионных тестов. Выбирай реально доступный путь, не считай настроенный MCP уже подтверждённым runtime.

Если инструмент заметно помогает цели, сам предложи 1–3 подходящих кандидата и коротко объясни, что каждый разблокирует. Сначала проверь уже имеющиеся возможности. Использование и настройка остаются в данных полномочиях: новое предложение не разрешает оплату, внешние записи или установку всех кандидатов.

2. Возьми минимальный набор по маршруту; при пробеле используй [библиотеку знаний](KNOWLEDGE-LIBRARY.md). Уже подходящее подключение предпочтительнее новой установки. Не предполагаются наличие Blender, 21st.dev, Higgsfield, ключей или платных лимитов.
3. Выполни ограниченную пробу, затем докажи основной путь на текущем артефакте. Оплата, публикация, доступ к аккаунтам и разрушительные действия остаются в исходных полномочиях; справочник не расширяет их.
4. При точном блокере подготовь всё независимое и сообщи: отсутствующая возможность → влияние на приёмку → доступная альтернатива → конкретное действие/решение. Не маскируй отсутствие backend картинкой. Не устанавливай все кандидаты и не загружай все правила в контекст.

Маршрут меняется при изменении цели или зависимости. Сохраняй один актуальный план и доказательства в проекте; таблица является механизмом выбора, а не дополнительным пакетом обязательной документации.
